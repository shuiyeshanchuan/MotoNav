# MotoNav v8.3.68 测试版 · 采样调度与完整行程日志

Android `v8.3.68 / versionCode 170`，1.75C `v7.12.9-nav.15-imu-sampling-log-test`。

11月8日骑行约19分钟，保存17,358组数据，序号和文件校验正常，但25 Hz计划时隙中有11,251个未采到，实际15.17 Hz。本轮解决采样与显示共用主循环的问题，并补齐下一次能够回放的证据；不调整急刹阈值或短信发送决策。

## 更新后怎么使用

1. 先更新手机App，再在小圆屏固件更新中点“检查测试版更新”安装nav15。签名BLE OTA即可，无须USB重烧、改分区或重新校准已有安装参考。
2. 正常开始导航，自动记录；正常结束导航，等待“连续记录已保存”，在行驶信息页导出最近会话ZIP。无需手动逐场景记录60秒。
3. 日常数据采集无需开启急刹报警测试。若要验证倒计时和取消，停车时用“保存并立即演练倒计时”，保持真实短信关闭即可；测试规则与v8.3.67一致。
4. 反馈ZIP和实际场景，例如静置、推车、正常刹车、路面颠簸，以及测试是否手动开启。不需要制造事故或危险急刹。

## 固件采集

- 保留QMI8658现有约112.1 Hz硬件ODR和量程、滤波、自检；专用采集任务5 ms轮询，只读取新数据，不重复旧快照凑频率。记录环仍按40 ms固定相位选择真实样本，目标25 Hz。
- IMU、触摸与电源芯片共用I²C，互斥覆盖完整寄存器读取和读缓冲消费。采集任务不绘图、不发送BLE、不写NVS；主循环继续独占健康聚合、安装参考和记录环。
- 新采集事件队列固定256条，每条52字节，原始数据13,312 B；另有队列状态、4,096 B任务栈和RTOS对象。按112.1 Hz约缓冲2.28秒，满后丢弃新事件并显式统计。原4096条×32 B的PSRAM记录环和写盘ACK保持。
- `missedSlots`仍统计40 ms计划时隙未产生记录的数量；`readErrors`保留读取失败；`overflow`同时涵盖采集队列丢弃和记录环覆盖，可能与漏采/序号缺口重叠，不能相加当作蓝牙丢包率。采集队列累计丢弃另有串口日志。
- START/STOP先消费命令时间栅栏之前的队列，防止旧样本跨会话或结束时遗漏已经采到的样本。超过队列容量的阻塞仍会丢数据，不声称无限缓存。

## 手机行程日志

原 `samples.csv` 和 `metadata.properties` 保持schema1及旧恢复语义；新增同目录 `journey.csv`，逐行CRC，保存：

- 原始BLE批头 `firstSeq/nextSeq/oldestSeq/count/boardNow/flags/boot`、完整批次样本及重复接收，避免把手机durable-next误当板端nextSeq。
- GPS瞬时速度、精度、原始定位时间、手机收到墙钟/单调时间、来源及真实/模拟标签；使用源坐标系，不伪造GPS。
- App/完整固件身份、安装参考状态和版本、检测器参数、导航/连接变化。
- 单次测试启停、门控变化、触发、倒计时取消/到期、短信提交/发送/送达或中断。稀疏关键事件落盘；高频状态合并，原始GPS和批次仍保留。

匿名事件token通过预算内的小型持久索引关联原行程，导航结束甚至新导航开始后的迟到回执仍写回原目录。未开始导航的演练单独标为 `diagnostic_only`，不冒充骑行。导出不包含联系人号码、骑行人姓名、提示或短信正文；GPS位置本身属于敏感数据，按用户选择本地导出。

写盘仍使用64项有界任务队列，额外日志缓冲最多64 KiB，正常每秒同步，并在IMU批次ACK、关键事件、结束和导出前同步。ACK需新侧录文件和旧样本文件均落盘；进程异常退出可能丢失尚未同步的非关键GPS/状态尾部，恢复会截掉坏CRC尾行和不完整原始批次。总预算仍为512 MiB、空闲空间下限64 MiB，不静默删除历史。

完整固件身份新增独立有界分片，支持默认MTU23并校验完整INFO正文CRC；丢片超时后手机有限次重查。旧文本FW前缀不再被视作完整身份；旧版设备仍可使用原协议。IMU批协议、导航数据和OTA签名格式不变。
