# MotoNav v8.3.66 测试版 · 导航连续六轴记录

Android `v8.3.66 / versionCode 168`，圆屏 `v7.12.9-nav.13-continuous-imu-test`。这是数据采集测试版，固件保持 `diagnostic=true`、`deviceTested=false`。没有开启事故判定、AI 训练、短信、拨号或紧急联系人通知。

## 更新与使用

1. 更新手机 App，再进入小圆屏固件更新，点击 **检查测试版更新**，安装 nav.13。普通稳定版入口不会推荐诊断包。此次应用层更新可以走现有签名 BLE OTA，无需更换分区或信任根；USB 救援完整镜像仍单独提供。
2. 手机和圆屏连接后，正常开始导航。无需手动“开始只记录”，也无需进行 60 秒采集。圆屏上电、打开 App、规划路线和巡航不启动本轮连续记录；模拟导航会单独标记。
3. “行驶信息”页查看已保存条数、序号缺口和漏采槽位。结束导航后等待缓存保存完成，点击 **导出最近连续记录**，取得 ZIP。正常退出再打开 App 后，最近文件仍可导出。
4. 先在停车/安全封闭环境验证息屏、后台和重连，再做完整一小时数据检查。不需要制造摔车或碰撞。本轮没有实机一小时通过结论。

## 实现范围与限制

- 保留现有 QMI8658 量程、约 112.1 Hz ODR、滤波、I²C 主循环读取及安装校准。新记录目标 25 Hz，使用固定 40 ms 调度槽位和真实读取时间，不复制旧样本填满时间线；地图刷新/动画造成的漏采单独计数。当前方案不能宣称是冲击峰值完整采集。
- 4096 条 × 32 字节 PSRAM 缓冲，共 128 KiB，按目标速率约 164 秒。BLE 断线仍采集已能读到的样本；满后覆盖最旧未确认数据并计数。圆屏断电会丢 RAM，缓存不是永久存储。
- 独立版本化 BLE 二进制批次，最多 8 条或等待约 250 ms 后发送，按实际 MTU 分包，含 session、boot、序号、读取时间、CRC、健康计数。手机同步写盘后 ACK，圆屏保留并重传未确认批次；新控制不刷新导航数据有效期。
- Android 使用 64 项有界后台写入队列，流式 CSV 和元数据按会话开始日期保存到排除备份的私有目录；记录预算 512 MiB、剩余空间下限 64 MiB，达到限制报错停止，不静默删除历史。清除 App 数据/卸载会删除私有记录，需先导出。
- 复用已有前台服务和唤醒锁；正常息屏/后台继续记录，厂商省电、强停、进程被杀和手机重启仍可能中断。下次启动恢复文件尾部并标记 interrupted，不自动恢复导航。重连发现上次遗留的孤儿采样会话会发送 STOP。
- 圆屏重启另开 boot 段，旧段尾部未知状态保留；结束排空超过 180 秒、服务关闭、新导航替换或写盘失败均保留已存文件并标记未确认尾部。存储失败后处理空间/存储问题，再重启 App。
- CSV 为带 CRC 的行式记录：S 行是六轴样本，B/G/T/D/E/F 分别标记启动段、缺口、板端统计、重复、注记和终止；ZIP 内 README 和 metadata.properties 说明字段。原始板端时间与手机接收时间分别保留，不假装已实现硬件 UTC 同步。

## 已验证

- Android Release 全量 clean 构建、原包名/原证书、启动类完整性校验通过；API 30 模拟器覆盖安装与冷启动通过。
- 原有 JVM 回归和安装参考测试通过；实际生产 OTA 候选选择 41 项通过。
- 固件 native 测试覆盖 CRC、MTU 23/185/517 分包、节流、重传、ACK 边界和身份、有限环溢出、断线恢复、停止排空、计时回绕、60 ms 轮询抖动、批次等待和非法样本。Arduino 1.75C 完整构建、SHA-256 和 RSA 校验通过。
- 新 Java 协议 62 项、文件存储 30 项、独立进程异常退出/CRC/尾行恢复 36 项通过。
- 实际 Release Kotlin 记录器与实际 Java 协议、存储模块的集成测试共 132 条断言通过。仅 Android/时钟/射频使用 JVM 替身；覆盖持久化后 ACK、去重、缺口、重连、boot 切段、ZIP、重启恢复、队列过载、排空超时和真实文件写入失败不 ACK。
- 32 MiB JVM 堆下流式保存 **90000 条合成样本（25 Hz × 1 小时的数据量）**，写入数/确认游标均为 90000，序号缺口 0，journal 8306511 字节，测试运行约 27.3 秒。这是合成数据验证，不是实际 BLE 连续一小时。
- nav.13 OTA 应用镜像 1383280 字节，SHA-256：`05385641d8bb70e8c6505bc02ff3fd16469cee1b0cc98df87abc0185537350eb`。

真实手机/圆屏的导航、息屏、后台、一小时 BLE、断线补传与 OTA 仍待验证。低 MTU 或主循环阻塞可能导致实际采样/传输率下降，应核对实际时间间隔和各类缺口，不能只检查目标采样率。
