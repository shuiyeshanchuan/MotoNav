# MotoNav v8.3.67 测试版 · 急刹提醒与测试短信

Android `v8.3.67 / versionCode 169`，圆屏 `v7.12.9-nav.14-brake-sms-test`。先打通“急刹测试触发 → 倒计时 → 手机/圆屏取消 → 未取消则发测试短信”的链路，保留现有导航、安装姿态参考与连续六轴本地记录。此版不代表事故判定已完成。

## 更新与使用

1. 更新手机 App，再使用小圆屏固件更新中的 **检查测试版更新** 安装 nav.14；普通稳定版入口继续排除诊断包。应用层签名 BLE OTA 即可，USB 完整镜像只用于救援。
2. 打开 **设置 → 急刹报警测试与紧急联系人**，填写姓名、一个联系人号码、提示文字、0–60 秒倒计时（默认 30 秒）。行驶信息页也有入口。
3. 先保持真实短信开关关闭，点击 **保存并立即演练倒计时**，验证手机/圆屏长按约 0.5 秒取消；再验证不取消时显示“演练完成，未发短信”。停车即可做，无需制造急刹、摔车或碰撞。
4. 需要验证真实短信时，先告知该测试联系人，明确选择有效的短信 SIM 并授予权限，打开 **本次测试允许发送真实短信** 后重新保存并演练。短信固定带“急刹测试，未确认事故”标识，附姓名和可信位置；旧定位/无定位如实标记。
5. 需要由传感器触发时，点击 **保存并开启一次急刹测试** 后开始真实导航。每次开启最多触发一次，之后需手动重新开启；巡航、模拟导航及历史补传不触发。仅在安全封闭场地验证，不必为了测试在公共道路急刹。

## 行为与边界

- IMU 动态加速度和新鲜 GPS 减速双证据在手机匹配，初始阈值只为测试链路，尚未完成真实骑行调参；弱 GPS、低速倒车等可能不触发，不视为已经具备事故保护。
- 自定义提示在手机和圆屏显示。圆屏只有收到手机确认才显示取消成功；蓝牙断开时提示请求待确认，不能把本地长按当作取消成功。
- 0 秒触发后立即处理，没有可用的取消窗口。返回、切换 App 或结束导航不等于确认平安。
- 短信发送认领先落盘，重复事件/回执不自动多发。提交后不可撤回，部分失败或状态未知不自动重试；发送提交、成功送达报告和联系人已读严格区分。
- App/手机重启不自动重新开启测试，也不补发中断的倒计时或已认领短信。服务停止、进程被杀、权限/无 SIM/无信号、锁屏及厂商省电策略仍可能让链路失效。
- 保持 `diagnostic=true`、`deviceTested=false`。现有 `AccidentSafetyModel` 仍只记录；本轮没有训练 AI、开启正式事故通知或拨打公共急救号码。

## 验证

- Android 全量 clean Release 构建、原包名/原证书和启动必需类检查通过。
- API 30 模拟器安装最终 APK 并冷启动通过；实际操作确认设置校验/保存、30 秒倒计时、短按不取消、长按取消、切后台后到期演练结束未发短信。测试时 `SEND_SMS` 未授权、真实短信开关关闭；0/60 秒及进程恢复等边界由生产类集成测试覆盖，不冒充已经逐机验证。
- Java 急刹检测器 1138 项、倒计时模型 808 项通过。实际 Release Kotlin 控制器、短信发送器和接收器 146 项集成断言通过，使用真实本地 JSON/AtomicFile 及 Android/时钟/SMS 替身，覆盖零秒、权限与 SIM、两端取消、持久化失败、重复/旧 token 回执、送达状态、重启不补发及长短提示缓存。
- 原有 JVM 回归、安装参考、连续协议/文件存储/恢复及实际记录器集成检查通过。未改变 nav.13 的原始数据记录与 ACK 语义。
- 固件报警 native 测试及连续 IMU 回归通过；1.75C Arduino 完整构建、RSA 签名及 SHA-256 校验通过。用实际页面代码生成的五种报警状态图已检查布局。
- 所有电脑短信测试都使用替身，**未发送真实短信**。真实手机/圆屏的急刹触发、取消、锁屏后台和联系人实际送达仍待实机验证；不能把编译或模拟器通过视为这些验收已完成。
