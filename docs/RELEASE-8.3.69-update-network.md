# MotoNav v8.3.69 测试版 · 更新检查超时修复

Android `v8.3.69 / versionCode 171`。圆屏沿用 `v7.12.9-nav.15-imu-sampling-log-test`，本版只需更新手机 App。

## 问题与改动

原 App 每次检查下载最近30条 Release 列表；圆屏检查还逐个串行读取历史索引。当前一次稳定检查20个请求、测试检查25个请求，单次等待最多10秒连接加30秒读取，索引失败后继续扫描，造成长期显示“检查中”。App 检查元数据的读取超时为60秒。

同一代理路径实测，413字节的诊断索引经 `github.com/releases/download` 返回HTTP504，约12秒；使用官方 API asset 入口重定向至资产服务器则约1.9秒成功。仅凭504不能定位手机具体网关，但已确认客户端的请求数量和等待方式会放大故障。

- App、稳定固件、测试固件优先读取 `updates/latest.json` 小型目录，正常一次请求；raw入口失败切换官方 API contents，最后有限回退到 Release API。
- 元数据检查共用15秒总预算，每个来源最多4秒，总请求不超过6次，历史索引最多3个；DNS、连接、重定向、读取和线程排队均计入等待预算。阻塞网络工作使用有限线程和队列；超时取消并异步关闭连接。
- 同时或15秒内重复检查复用成功目录，不把旧缓存当成联网成功。HTTP错误、超时和损坏数据明确报错，不再静默吞错并宣称没有固件。
- 下载优先官方资产API，失败后使用同仓库Release地址；APK流式写盘，换源前清空残片。安装包签名、包名和版本验证、固件RSA/哈希/板型验证保留。大文件下载独立于15秒元数据时限。
- 圆屏设备信息读取最多5秒；OTA重启、重连并读到目标固件INFO后直接确认成功，去掉额外联网查询。退出页面后的旧Activity不再启动安装器或更新视图。

稳定入口继续排除诊断固件；测试入口仍需主动点击。导航、记录协议、事故阈值和短信规则保持既有行为。

## 发布目录维护

每次发布资产后执行 `scripts/update-github-feed.ps1`，再提交并推送 `updates/latest.json` 到 `175c-ota-one-click`。目录只从公开Release生成，包含官方资产ID、大小及App哈希；失败不覆盖旧目录，历史稳定入口滚出第一页时先核对旧资产仍然公开再保留。

发布电脑已登录GitHub CLI时可给两个脚本加 `-UseGhAuthentication`，避免发布核验耗尽共享出口的匿名API额度；App本身仍读取公开目录，无需登录或Token。

最后执行 `scripts/verify-github-release.ps1 -Tag <tag> -ExpectedCommit <build-commit> -RequireApp -RequireFeed -AssetDirectory <folder>`。目录与Release均需公开可读且资产一致，不能只上传文件后忘记更新目录。
