# MotoNav v8.3.65 测试版 · 修复更新发现与固件候选选择

Android App：`v8.3.65` / `versionCode 167`。本轮仅更新手机 App，圆屏继续使用 `v7.12.9-nav.12-mount-reference-imu-test` 的原镜像、manifest 和签名；已安装 nav.12 无需重刷。Android Release 构建、原证书签名、启动类校验和 API 30 模拟器冷启动通过；OTA 策略共 41 项检查通过。本轮没有真实手机/圆屏 OTA 验证结论。

## 两个根因与修正

1. **发布 tag 指错提交。** v8.3.64 最初使用 `main` 的旧提交 `6a18c8d` 作为 tag，Release 在匿名 API 列表位于第 31 条，超出 App 查询前 30 条的范围。已纠正为 v8.3.64 实际构建提交 `fa7d2de39ed4ca6769b50ed9a3ffed2a75b4da15`，发布目标为 `175c-ota-one-click`，匿名 API 首条恢复为 v8.3.64；本次修复不改变 v8.3.64 资产。v8.3.65 发布必须另以本轮修复提交的完整 SHA 执行 `--target`，并运行发布后校验脚本。
2. **客户端把“不可比较”误认为“同版本”。** `nav` 与 `power` 属于不同固件系列，原版本比较在此情况返回 `0`。候选选择又把 `0` 当作版本相同并优先稳定包，因此检查测试版时，先找到的 nav.12 诊断包可能被随后遍历到的旧 power.18 稳定包覆盖。现在只有**版本字符串精确相同**时才适用稳定包优先；跨系列保留先找到的发布候选，同系列继续比较数字版本。

v8.3.64 仍可见，但 tag 修正不能修复已经安装的客户端候选逻辑，建议升级手机至 v8.3.65。普通“检查稳定版更新”仍排除诊断包，圆屏测试固件仍需显式点击“检查测试版更新”。

## 如何更新

- 在手机安装 `v8.3.65` App。
- 圆屏已是 nav.12：无需重新下载或刷写圆屏固件，直接继续使用安装姿态校准。
- 圆屏尚未安装 nav.12：更新 App 后进入圆屏固件更新区，点击“检查测试版更新”，确认候选为 `v7.12.9-nav.12-mount-reference-imu-test` 再升级。

安装姿态归零仍按 [v8.3.64 说明](RELEASE-8.3.64-175C-mount-reference.md)：固定安装、平地扶正车体（非侧撑）、熄火静置，手机发起后保持约 5 秒。手机和圆屏显示静态相对总倾斜，不代表真实动态左右压弯；原始样本、零偏、事故 CSV、事故阈值和通知状态均不改变，事故自动通知继续关闭。固件保持 `diagnostic=true`、`deviceTested=false`。

## 验证状态

- Android `clean assembleRelease` 通过，版本 `8.3.65/167`，原包名与签名证书匹配，启动类完整性检查通过。
- API 30 模拟器覆盖安装、冷启动与进程存活检查通过。
