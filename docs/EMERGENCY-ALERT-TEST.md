# 急刹报警测试闭环

适用版本：Android `v8.3.67 / versionCode 169`，1.75C `v7.12.9-nav.14-brake-sms-test`。本轮按用户要求先贯通提醒、取消、短信链路，沿用 nav.13 的连续原始数据记录，不改 `AccidentSafetyModel`，不训练 AI。

## 1. 使用方式

1. 先更新 App，再在小圆屏固件更新中使用“检查测试版更新”安装 nav.14。应用层签名 BLE OTA 即可，不需要换分区、Bootloader 或信任根。
2. 进入“设置 → 急刹报警测试与紧急联系人”（行驶信息页也有入口），填写骑行人真实姓名、一个紧急联系人手机号、提示文字和 0–60 秒倒计时，默认 30 秒。
3. 默认关闭真实短信。先保存并立即演练倒计时：手机或圆屏按住约 0.5 秒取消；再演练一次不取消，确认出现“演练完成，未发短信”。返回、切换应用、停止导航不等于确认平安。
4. 验证真实短信时，先告知该测试联系人，再打开“本次测试允许发送真实短信”、授予短信/通知/电话状态权限并明确选择有效 SIM，保存并立即演练。未取消则只提交一次短信，不自动重试。0 秒没有可用的取消窗口。
5. 需要由急刹触发时，点击“保存并开启一次急刹测试”，然后开始真实导航。每次开启最多触发一次，触发后必须手动重新开启；重启 App 不会自动重新开启。先用停车演练检查链路，再在安全封闭场地验证传感器触发，不必制造摔车或碰撞。

默认提示文字：

> 检测到您急刹了，若您平安无事，长按圆屏或手机弹窗确认取消报警

短信保留固定测试标识，姓名和位置由实际事件填充：

> 【MotoNav急刹测试，未确认事故】您的亲人/好友某某触发急刹报警且未确认平安，疑似发生事故。地点：当前定位或最后定位的高德链接和精度，旧定位另附时间。请先联系本人核实；确认需要救援时请报警。

没有可信位置时明确写“位置暂不可用”，旧定位标注时间和“非实时”。不伪造实时位置、不自动拨打公共急救号码。

## 2. 本轮触发器

触发判断在手机执行，使用圆屏 QMI8658 原始六轴和手机 GPS 双证据；圆屏不具备脱离手机发送短信的能力。

- 仅用户开启的本次真实导航有效，规划页、巡航和模拟导航不触发。
- 连续 IMU 仍以 nav.13 的 25 Hz 调度槽采集并保存真实读取时间。先验证 boot、序号、健康标志和时间，重连后等待实时流恢复；历史补传不得触发提醒。
- IMU 使用重力向量低通估计，扣除重力后动态加速度模长至少 `2.5 m/s²`、持续至少 `120 ms`；不依赖屏幕朝上安装，也不把四姿态数据直接写成零偏。
- GPS 起始速度至少 `12 km/h`，最多 `2.5 s` 内速度下降至少 `8 km/h`，估算减速度至少 `2.5 m/s²`；定位精度不超过 `30 m`，定位年龄不超过 `1.5 s`。
- 两种证据必须在 `2 s` 时间窗内匹配；无效定位、IMU 不健康、时间倒退、断线或大间隔会清除证据。

这些阈值只用于急刹链路测试，尚未经过真实骑行调参。急刹不能证明发生事故，缓慢倒车、低速摔车、隧道失去 GPS 等也可能不触发；不据此宣称有事故保护能力。

## 3. 倒计时与 BLE

复用已有加密配对连接和命令队列，增加独立能力 `CAP,EMG,1`，不改变导航数据有效期或 OTA 协议。

- 手机 → 圆屏：`#EA,<8位十六进制事件token>,<state>,<剩余秒数>`。
- 圆屏 → 手机：`EA,C,<token>`，请求取消当前倒计时。
- state：`1` 倒计时、`2` 已取消、`3` 处理/发送中、`4` 短信已提交、`5` 失败、`6` 未知、`7` 演练结束未发短信、`8` 中断。
- 同一事件 token 持久递增；旧事件/旧页面不能取消新事件。圆屏只在收到手机 state 2 后显示取消成功；未确认前有限频率重发取消请求。收到 state 3–8 后停止取消重发，因为已不能撤回处理。
- 倒计时归零而手机未回复时，圆屏显示等待手机处理，不能自行显示“已发短信”。PWR、配对及 OTA 界面优先于报警覆盖页。
- 提示文字通过 bitmap 槽 14/15 显示；图片传输不可用时仍有中文备用提示和倒计时。

## 4. 手机状态与持久化

`EmergencyAlertController` 在主线程串行处理触发、取消和短信认领；倒计时使用单调时钟。各事件 JSON 和 `latest.json` 使用 `AtomicFile` 保存到 `noBackupFilesDir/emergency_test`，包含 token、来源、姓名/联系人配置快照、时间、触发证据、短信内容与每段发送/送达结果。

- 先持久化 `SEND_CLAIMED/SENDING`，再调用所选 SIM 的 `SmsManager`；持久化失败不继续发短信。
- 未开启真实短信时只写演练结果，不调用短信发送 API。
- 短信提交后不可撤回；发送失败或结果未知不自动重试。多段短信可能部分成功，记录会明确保留失败，重复回执不能用成功覆盖既有失败。
- “已提交”只表示各段发送结果成功。只有有效的成功状态报告才称“有送达回执”，仍不代表联系人已读；缺少/无法解码/临时状态报告保持未知。
- GSM 送达只接受 TP-Status `0`；已转发但无法确认、替换、保留值不冒充送达。依据 [Android SmsMessage.getStatus](https://developer.android.com/reference/android/telephony/SmsMessage#getStatus()) 和 [ETSI TS 23.040 §9.2.3.15](https://etsi.org/deliver/etsi_ts/123000_123099/123040/16.00.00_60/ts_123040v160000p.pdf)；当前未核验 CDMA 状态报告，保守显示未知。
- 后到的回执归属于原 token 的事件文件，不覆盖新事件。
- 正常息屏和后台复用现有导航前台服务；全屏提醒由 Android 权限、通知渠道和厂商策略决定，不可用时可能只显示通知。
- BLE 暂断时手机倒计时继续，圆屏无法确认取消；重连同步当前状态。手机服务停止、进程被杀或手机重启会中断未完成流程，不在恢复时自动补发，避免重复或过期通知。
- 如果进程在短信认领后退出，短信 API 可能已经执行，不能断言“未发送”。圆屏中断页提示在手机核实结果，手机保留回执和“未自动补发”状态；仍需核对联系人是否收到。
- 关闭系统通知、无短信权限、无有效 SIM、欠费/无信号、手机断电等都会影响链路。GPS/IMU 不可用时不猜测触发；发送失败或未知保留真实结果。

## 5. 验收与反馈

停车演练依次记录：默认不发短信、手机长按取消、圆屏长按取消、0/30/60 秒、不取消的真实测试短信、BLE 断线重连、App 切后台/息屏、权限撤销、无 SIM、进程/手机重启。反馈 App/固件版本、倒计时设置、两端最终文字、是否收到短信及设置页“查看最近测试记录”；不要把长按取消请求本身当作取消成功。

真实 IMU/GPS 急刹触发、厂商锁屏/省电、圆屏触摸与 SIM 送达需要真实设备验证。电脑测试、模拟器和编译通过不等于上述实机验收完成。后续用日常骑行负样本和封闭场地回放独立改进事故算法，不改变短信幂等、取消及真实状态的边界。
